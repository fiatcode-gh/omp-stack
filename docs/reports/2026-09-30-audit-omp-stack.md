# Audit: omp-stack (2026-09-30)

## Provenance and scope

- Repository: `omp-stack`, HEAD `fc3504b5088a9002834e1146cf9bb48014cb6a6b` (`main`, clean tree, in sync with `origin/main`).
- Scope: whole repository. The product is doctrine loaded into OMP sessions (`agent/AGENTS.md`, 3 rules, 10 agents, 13 skills with references) plus runtime code (`agent/extensions/*.ts`, `agent/lib/ai-memory.ts`, `scripts/omp-stack`, `scripts/flow-sessions`, the mailbox and handoff-validator scripts), tests and docs.
- Method: `flow-review` audit mode. Five read-only lenses ran as subagents on `claude-fable-5-1:high` (session-only role override, not persisted): DOC (doctrine coherence, added because the product is prose), CDH (`flow-audit-code-health`), TTC (`flow-audit-tests`), DST (`flow-audit-docs`), SEC (`security-reviewer`). Main verified every Critical/Important finding by reading the cited code or reproducing it in a `mktemp` directory; Minor findings were sampled. Duplicate root causes across lenses are merged below.
- Baseline: `sh tests/run.sh` green at HEAD; GitHub CI green for the same commit on `ubuntu-latest`.

## Rating: At risk

One verified Critical (the installer reports success after a failed profile resolution and attempts root-level symlinks). Everything else is Important or Minor. The Critical has a narrow precondition; see A1.

## Coverage summary

Read in full: all loaded doctrine (AGENTS.md, rules, agents, every `SKILL.md`, every `references/*.md`), all extensions and scripts, all tests, all docs and decision records, both profile configs, CI workflow. Executed: the test suite, `validate.py`, and throwaway probes for the installer, both guards, the exclude guard, the pattern matcher port, the mailbox and `flow-sessions`.

## Verified findings

Severity per `flow-review` audit lenses. Confidence is the verifier's after Main's check. "Disposition" is the proposed path; the user decides.

### A. Runtime code

**A1 — Critical (75) — Installer succeeds and prints `linked …` after a profile fails to resolve; as root it would retarget `/lib`.**
`scripts/omp-stack:15,24,56,79`. `profile_dir` calls `fail` (which runs `exit 1`) inside `$(…)`, so only the subshell dies and `dir=""`. `install_profile` is invoked as `install_profile "$profile" || rc=1`, which suspends `set -e` for its whole body. Reproduced with a fake `omp` that resolves `ollama-cloud` and fails `anthropic`: the run prints `error: could not resolve OMP profile 'anthropic'`, then `ln: failed to create symbolic link '/AGENTS.md'` … `linked /lib -> …/agent/lib` … and exits 0. `link_owned` refuses only non-symlink targets; on usrmerge systems `/lib` is a symlink, so a root run would replace it. Docs (`MODEL-ROUTING.md:33`, `MIGRATION.md:26`) promise a non-zero exit. Precondition: `omp` on PATH and `omp --profile <p> config path` failing for a profile after the first one succeeded (the first failure aborts correctly via `install_shared`). Verified: reproduced by Main in a temp HOME. Remedy: make `profile_dir` print nothing on failure and have callers check `[ -n "$dir" ] || fail`; check `ln` status before printing `linked`; refuse an empty or `/` destination; add an installer test with a failing fake `omp`. Disposition: **fix**.

**A2 — Important (95) — Evidence-capsule guard does not trim the agent name, and its `id:` marker is a bare substring.** `agent/extensions/flow-evidence-guard.ts:18,24`. `if (agent !== VERIFIER) return;` while the governance guard trims (`flow-governance-guard.ts:270`, comment: "OMP trims the agent name before resolving it"). `" flow-evidence-verifier"` with a capsule-less task passes; a capsule whose only `id:` is inside `grid:` or `valid:` also passes. Governance still requires Scope and acceptance, so dispatch is not fully ungated, but invariant 37 ("missing manifests are rejected before dispatch") is advisory. Verified: source read; both lenses ran probes. Remedy: share the trim helper; anchor markers at line start (`/^\s*-?\s*id:/im`); add padded-name and loose-marker cases to `tests/flow-evidence-guard.test.mjs`. Disposition: **fix**. (Merged CDH-2, CDH-7, TTC-1.)

**A3 — Important (85) — `worktreeIdentity` swallows every `git diff` failure, so a >1 MiB tracked diff or an unborn HEAD silently drops tracked changes from the acceptance fingerprint.** `flow-governance-guard.ts:141-154`. The `catch` meant for an unborn HEAD also catches `execFileSync`'s ENOBUFS (default `maxBuffer` 1 MiB) and substitutes `git diff --no-index /dev/null /dev/null`, which returns `""`. Main reproduced ENOBUFS with a 2 MB modified tracked file. After that, edits to tracked files no longer change the fingerprint, so `verifierGateError` cannot detect post-acceptance mutation and `status` says `acceptance: current`. On an unborn HEAD the same path ignores staged content (probe: stage `v1`, accept, stage `v2`, verifier passes). The fallback subprocess is a no-op. Remedy: branch on `head === "UNBORN"` explicitly (diff against the empty tree), let other errors propagate (preflight already fails closed), and stream the diff into the hash or raise `maxBuffer`; add a >1 MiB and an unborn case to the governance test. Disposition: **fix**. (Merged CDH-3, SEC-2.)

**A4 — Important (90) — Exclude guard corrupts a user rule and fails to hide `.flow` when `info/exclude` lacks a trailing newline.** `agent/rules/flow-artifacts.md` snippet and `flow-governance-guard.ts:93-100`. Reproduced by Main: with `printf 'build/' > .git/info/exclude`, one run yields `build//.flow/`; `git status` then shows both `?? .flow/` and `?? build/` (the user's rule is destroyed). The TS copy appends the same way. Remedy: ensure a trailing newline before appending in both copies; add a newline-less fixture to `tests/flow-exclude.test.sh` and the governance test. Disposition: **fix**.

**A5 — Important (85) — Publication backstop misses `git -C … push`, `git -c … push` and `env … gh …`, while the doctrine itself teaches `git -C`.** `profiles/*/config.yml` `bash.patterns` are anchored at the command start (`git push*`); `flow-external-session/references/external-worktree.md` instructs `git -C "$wt" …`, so an agent on an external worktree will naturally spell `git -C "$wt" push`. `tests/bash-patterns.test.mjs` has no such spelling in its must-prompt list. Verified: pattern list and matcher port read by Main. Related, lower severity: the list also omits `gh issue create/close/edit`, `gh pr ready/reopen`, `gh release edit/upload/delete`, `gh repo edit/delete`, `gh secret set`, `gh workflow run` (SEC-6). Remedy: add `git -C * push*`, `git -c * push*`, `env * git push*`, `env * gh *` patterns and the missing `gh` writes to both profiles; extend the must-prompt list; record any residual next to the `GH_TOKEN=x gh api` note in `OMP-COMPATIBILITY.md`. Disposition: **fix**. (Merged TTC-3, SEC-6.)

**A6 — Important (90) — Gate state is hand-editable and no doctrine forbids it.** `flow-governance-guard.ts:84-92,226-234`. `readState` accepts any `{version:1, scopes}` JSON; an approval is `{path, sha256, approvedAt}`. The native prompt and `ctx.hasUI` protect only the `flow_gate approve` path. A Main that writes `.flow/runtime/gates.json` with the `write` tool and a `sha256sum` passes planner/writer preflight. `flow-artifacts`, `flow-safety`, `AGENTS.md` and `ARCHITECTURE.md` name the file but never say it is written only by `flow_gate`. Threat model: a misbehaving or injected agent, not an external attacker; the field-trial ledger records a session that hit 7 gate rejections, which is exactly when a hand edit becomes tempting. Remedy: one line in `flow-artifacts` ("`.flow/runtime/` is written only by `flow_gate`; a hand-written record is not an approval") pinned by `validate.py`; optionally a `tool_call` hook that blocks `write`/`edit` on that path. Disposition: **fix** (doctrine line now; hook is backlog).

**A7 — Minor (90) — `accept` fingerprints before `.flow/` is excluded.** `flow-governance-guard.ts:445-454`. On a checkout whose exclude entry does not exist yet, the first `accept` hashes `.flow/**` as untracked, then `writeState` adds the exclude, so the very next verifier dispatch is blocked with equal heads and a misleading "parallel tool batch" hint. Normally `approve` runs first and adds the entry, so this only bites when approvals were skipped. Remedy: call `ensureFlowExcluded` at the top of `worktreeIdentity`. Disposition: **fix with A3**.

**A8 — Minor (90) — `flow-sessions list` aborts on the first unparseable transcript line.** `scripts/flow-sessions:27-30`. One in-flight or truncated session hides the whole listing that `FIELD-TRIAL-AUDIT.md` step 1 depends on. Also hardcodes `~/.omp/profiles` (the installer honours `PI_CONFIG_DIR`) and counts only batch `tasks[]` dispatches, not single `agent:` calls. Remedy: skip undecodable lines with a stderr note; read `PI_CONFIG_DIR`; count `args.agent`. Disposition: **backlog**. (Merged CDH-6, CDH-12.)

**A9 — Minor (70) — `link_owned` retargets any pre-existing symlink without inspecting it.** `scripts/omp-stack:28-34`. A user-managed link (dotfiles, another skills directory) is replaced silently; only a regular-file `config.yml` gets the `cmp -s` protection. May be intentional for ai-stack migration; not documented. Remedy: warn or refuse when `readlink -f "$dst"` is outside `$ROOT`, or document the behaviour. Disposition: **watch**; decide with A1. (Merged CDH-9, TTC-12.)

**A10 — Minor — Small cleanups.** `agent/extensions/ai-memory.ts:12,16` keys the project on `process.cwd()` instead of `ctx.cwd` and exports an unused `HARNESS`; `mailbox:343` leaks a backslash into a user-facing message (`worker\'s`); `tests/validate.py` has a duplicate `import json` (:2, :252), mixed absolute/relative paths in errors, and a dead tripwire for `flow-orchestration-guard.ts` (:130-133); `flow-governance-guard.ts` and `flow-evidence-guard.ts` open without a module header naming the invariant and state file they own. Disposition: **backlog**, batch with the next guard change.

### B. Tests and contracts

### C. Doctrine coherence

**C1 — Important (70) — `AGENTS.md` demands a plan approval before any substantial writer; `flow-execution` allows `Plan: NONE`.** `AGENTS.md:22` "For substantial work, do not dispatch the first production-writing worker until the user approves the completed execution-grade plan." `flow-execution/SKILL.md:26` "Write `Plan: NONE` when the approved contract's work needs no separate plan … record approval with `flow_gate` `present` `kind=implementation`".
